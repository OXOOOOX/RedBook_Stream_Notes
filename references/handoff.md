## 保留哪些决策，避免重新走弯路

1. **只维护一份源码。** 仓库根目录直接兼作 skill，服务代码保留在 src；不要为了安装 skill 再复制一套业务代码。完整目录才可安装，Python wheel 不能代替 skill ZIP。
2. **文档反映真实能力。** 本次解决的是分发、路径、依赖和调用保护；录音与识别仍串行，识别期间会漏录。不要把包装完成写成采集架构已修复。
3. **原文是笔记证据。** refined_note.md 含财经硬编码规则，最终笔记由 agent 根据完整原始片段另行整理。数字、否定、条件和疑词需要保留。
4. **区分运行与离线整理。** 已有文字材料可直接整理；新直播才需要桌面、播放与回录。doctor 通过、listening 状态和正确非空转写代表不同阶段。
5. **使用完整快照导出。** note 只展示部分旧原文，API snapshot 才含进程中所有片段。failed 任务导出也可能为 partial:false，仍需按错误和缺失范围说明交付不完整。
6. **保留发布版本对应关系。** 从明确提交构建附件，校验下载结果。文档更新可以继续进入 main；历史版本附件与校验值用于复现该历史版本。

项目维护者明确要求禁止批量删除文件或目录，已写入仓库和安装包根目录的 [AGENTS.md](../AGENTS.md)。不能用清理缓存、重建环境或释放磁盘空间作为批量删除的理由；只允许一次删除一个明确路径的文件，批量清理由用户手动处理。

## 解释那封失败通知

历史运行 [33728643575](https://github.com/OXOOOOX/RedBook_Stream_Notes/actions/runs/33728643575) 对应中间提交 `b8e5b03`。当时工作流先到 GitHub，完整代码还未同步，Ubuntu 在执行 `python scripts/package_skill.py --check` 时报告文件不存在；矩阵中的 Windows 作业随后取消。

背景是普通 Git/CLI OAuth 凭据缺少 workflow scope。通过已具备相应授权的 GitHub App 上传工作流后，再 fetch、合并并正常推送完整项目，后续运行通过。没有强推、没有将 token 写入仓库，也没有修改仓库可见性。

排查类似邮件时先对照运行的 commit SHA、分支/tag 和最新运行，不能只看邮件中的红色状态；对历史不完整提交反复重跑不会补齐那次提交的文件。当前凭据权限仍以实际查询为准，不能把此前某个 App 的成功当成所有凭据永久有权限。

最终 CI 还有一条非失败提示：使用的 Actions 版本声明旧 Node.js 20 运行时，runner 切换为 Node.js 24 后完成检查。后续升级 Actions 时核对上游版本并重新验证；该提示没有导致 v0.1.0 检查失败。

## 可重新执行的笔记质量样例

输入保存在 [offline-note-evaluation.json](../assets/offline-note-evaluation.json)。它是此前离线验证使用的模拟材料，包含精简 snapshot 和用户请求，不是完整的 API 响应测试夹具，也不含用户真实直播数据。

让 agent 只读取 skill 和这份输入，在一个新的评估目录保留快照并生成 final_note.md。不要提供预先写好的答案，也不启动服务、浏览器或录音。完成后由评估者检查：

- “不讨论资金流，不判断压力位”没有被改成财经观点。
- 今天 300 名、昨天 200 名访客没有混淆。
- “未来七天测试标题”保留为安排，“3%”保留为目标，没有写成已经达成。
- “星流宝”保持待核对，不凭猜测替换。
- failed、设备断开、片段缺失与累计录音时间的范围说明完整；没有推断直播已经下播。
- 原始 snapshot 内容未改写，未提供时间范围的缺失原因仍标为未知。

这些是行为验收条件，不要求逐字匹配某篇范文。此前一次评估通过不保证之后所有模型和 skill 修改都通过。

## 新机器与新聊天的接手入口

先克隆项目或解压 v0.1.1 安装包，阅读 README、AGENTS.md 和本文件；按照[安装指南](setup.md)创建环境。为了复现指定版本，可在独立克隆中 checkout 对应 tag。安装与诊断时保留实际解释器、数据路径、FrameNotes 选择结果，避免依赖旧聊天里的临时目录或进程 ID。

可直接复制给新的 agent：

```text
请接手 OXOOOOX/RedBook_Stream_Notes。先阅读仓库 AGENTS.md、README.md、
references/handoff.md、references/engineering-lessons.md 和 references/validation.md。
核对当前分支、远程状态和我指定的目标，再开始修改。
当前安装包版本为 v0.1.1；后端仍存在串行漏录、内存任务和停止幂等问题。
区分已修复、CLI 规避和未实现能力；笔记只依据原文，保留数字、否定和疑词。
遵守禁止批量删除文件/目录的约束。接下来的任务是：由我补充具体目标。
```

## 云端没有备份的内容

公开仓库和 Release 保存代码、工程经验、模板与合成测试数据。它们没有保存真实 runtime/jobs、exports、录音、个人笔记、浏览器登录态、凭据、模型权重、虚拟环境、机器音频路由或完整聊天。

如果这些内容仍有保留价值，应由用户选择私有备份位置单独保存；尤其是实际直播产物和成功设备配置，不能由代码和这份交接文档重新生成。整理项目知识不等于这些私人资料已经备份。任务历史在运行进程内存中，磁盘文件也不等于完整任务可自动恢复。
