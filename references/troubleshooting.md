# 故障排查与当前限制

本页只描述仓库已实现的能力。诊断时先读取 `GET /jobs/{job_id}` 的 `status`、`error`、`chunks_completed`、`segments` 和 `note`，再查看该任务所需的具体文件。不要把“HTTP 服务正常”“浏览器已打开”“已有 WAV”当成成功转写的证明。

所有路径和链接示例均为占位值；先替换为当前安装目录或用户提供的链接。文件清理遵守上层任务约束：本 skill 不要求通过批量删除缓存、目录或录音来排障。

## 最短诊断顺序

1. 请求 `/health`。无法连接时先处理服务启动或端口问题。
2. 读取任务快照。`failed` 优先查看 `error`；404 优先核对服务进程是否重启或任务 ID 是否正确。
3. 查看自动打开的 Chromium 页面，确认目标直播能正常加载和播放。默认窗口是新建的独立浏览器上下文。
4. 确认直播声音输出到系统默认扬声器对应设备；检查预检和正式 WAV 的音量，而不只检查文件大小。
5. 确认实际选中的 ASR 后端及其依赖，核查该段是否存在有效 `transcript.json`。
6. 最后核对笔记文件、时间轴和规则清理结果；不要只依据精炼摘要反推原始发言。

可复用的只读快照命令：

```powershell
$baseUri = 'http://127.0.0.1:8000'
$jobId = 'REPLACE_WITH_JOB_ID'
Invoke-RestMethod -Uri "$baseUri/health"
$snapshot = Invoke-RestMethod -Uri "$baseUri/jobs/$jobId"
$snapshot | Select-Object id, status, chunks_completed, ended_reason, error, updated_at
$snapshot.note
```

完整字段和停止流程见 [API 参考](api.md)。

## HTTP 服务与安装

### 连接被拒绝、找不到页面或启动后立即退出

服务的主页面是 `/viewer`，没有为根路径 `/` 定义业务页面。确认使用实际监听端口和 `http://127.0.0.1:<端口>/viewer`。`/health` 返回 `ok` 只说明应用能响应。

在仓库安装环境中检查 Python 版本和依赖是否来自同一解释器：

```powershell
Set-Location 'C:\work\redbook-live-notes'
python --version
python -m pip show fastapi uvicorn playwright soundcard soundfile numpy faster-whisper
```

项目声明 Python 3.10 及以上。出现 `ModuleNotFoundError: redbook_stream_notes` 时，确认已按仓库安装说明安装当前项目，或启动时为 Uvicorn 指定 `--app-dir src`。检查进程日志中的实际异常，不要用重复创建直播任务验证一个尚未启动成功的服务。

### Chromium 可执行文件不存在

安装 Python 的 `playwright` 包不等于当前环境已具备浏览器二进制。使用启动服务的同一 Python 环境安装 Chromium：

```powershell
python -m playwright install chromium
```

安装失败时保留命令错误信息并处理下载或文件权限问题。仓库没有实现自动浏览器下载或复用桌面 Chrome 的逻辑。

### 创建返回 422

API 的 `url` 必须是单独的 HTTP/HTTPS URL；不要直接把整段分享文案作为此字段传入。完整分享文案可以粘贴到 `/viewer`，由其前端提取支持域名的链接。

检查 `chunk_seconds` 是否为 15–600 的整数、`max_chunks` 是否为 `null` 或大于等于 1 的整数，以及 JSON 的布尔值是否正确。查看响应中的 `detail` 定位字段。模型、语言和设备的字符串在请求阶段不做后端可用性校验，因此这些值有问题时也可能先创建成功、之后任务失败。

### 重启后旧任务返回 404，或者不同请求偶尔看不到任务

任务索引是模块内的内存字典。服务重启不会从 `runtime/jobs` 读取历史任务；磁盘目录存在也不能通过原 ID 重新连接。多进程部署中的各个进程也不共享任务索引。

当前应使用单个服务进程。开发热重载会重启应用，不能用于期望持续运行的录音会话。旧文件可以按具体任务目录读取，代码没有续录、恢复或历史导入 API。

## 页面加载、登录与播放

### 浏览器开了但直播没有开始

默认启动的是 Playwright Chromium，新建上下文，不会导入用户 Chrome 的现有 Cookie、登录态、扩展或历史资料。需要登录时，可在该可见窗口中正常完成网站要求的操作。服务没有实现验证码自动处理、持久登录 profile、Cookie 导入或登录完成检测。

页面导航等待 `domcontentloaded`，超时为 60 秒。检查窗口是否停在登录、跳转、网络错误、访问受限或无效直播页面。不能把这些页面视为可用直播源，也不能据此声称转写正在进行。

默认 `headless: false` 更便于观察播放状态。API 虽允许 `headless: true`，它并不增加登录能力，仍然依赖系统音频输出；当前实现没有针对无界面服务器配置虚拟声卡或音频转发。

### 取消静音没有生效

代码尝试悬停 `.main-player, .player-el, .xgplayer`，点击 `.xgplayer-icon-muted`，再把页面 `video`、`audio` 元素设为非静音、音量 1 并调用 `play()`。每轮最多尝试 5 次；这种逻辑依赖页面结构，网站更新后可能失效。

先在当前直播窗口中检查播放按钮、播放器音量和系统音量混合器。页面元素显示“播放中”也不代表输出设备能被录到；是否可录以 loopback WAV 的实际内容为准。项目没有通用弹窗关闭器，也没有针对所有播放器的适配层。

## 录音与静音

### `listening` 持续很久，但没有转写片段

`listening` 同时涵盖音频预检、录音和 ASR，没有分别暴露这些子状态。正式转写前需要至少完成一个分段；默认分段为 60 秒，此外还包括打开页面、探测声音、首次模型初始化或下载、以及转写计算时间。

查看 `chunks_completed`：

- 仍为 0：可能还在启动后的预检、第一段录音或首次 ASR 中。检查页面和服务日志。
- 持续增加但 `segments` 为空：可能每段静音而跳过 ASR，或者 ASR 对非静音音频没有识别出语音。
- 已有片段，之后不再增加：可能正在处理下一长段、转写耗时较久，或任务已经出错；以快照为准。

连续静音不会自动结束任务。需要固定段数的短时验证时，通过 API 创建 `max_chunks: 1` 的任务；正式分段仍须至少 15 秒。

### 笔记显示“音频预检仍为静音”或“当前分段录到静音”

录音器每次调用 `soundcard.default_speaker()`，再用其名称查找包含 loopback 的录音设备。它录制系统默认输出设备的回环声音，没有麦克风输入选择器，也不能只录某个浏览器标签页。

按顺序检查：

1. 自动打开的直播窗口确实有可听见的声音。
2. Windows 默认输出设备与浏览器音量混合器中的应用输出路由一致。
3. 耳机、蓝牙、显示器音频或虚拟声卡没有把直播路由到另一个设备。
4. 打开当前任务的具体 `probe/audio_probe_1.wav` 或 `chunk_0001/audio.wav` 验证实际内容；不要混淆旧任务文件。

当前设置为 16 kHz、单声道。预检每次最多录 3 段，每段 3 秒，达到峰值阈值就结束预检。由于正式循环第一段前会再次预检，探测可能执行多次并覆盖同名探测文件。即使探测一直静音，程序也会继续进入正式录音循环。

以归一化浮点幅值计算，正式分段 `peak < 0.0002` 时直接跳过 ASR，但会递增 `chunks_completed`。代码没有静音自动停止或“只检测到主播声音”的判定。

可使用项目现成函数对一个明确文件进行只读统计：

```powershell
Set-Location 'C:\work\redbook-live-notes'
python -c "from pathlib import Path; from redbook_stream_notes.jobs import inspect_audio; print(inspect_audio(Path(r'C:\work\redbook-live-notes\runtime\jobs\REPLACE_WITH_JOB_ID\chunk_0001\audio.wav')))"
```

如果未把项目安装到当前解释器，请先按安装说明完成环境配置。统计项包含采样率、秒数、RMS 和峰值；单看非零峰值仍无法确认内容是主播语音。

### 文件有声音，但很轻或有其他应用的声音

程序仅对 `0 < peak < 0.02` 的非静音音频执行放大，目标峰值 0.35，最大增益 80 倍，裁剪到 ±0.98，并覆盖正式 `audio.wav`。峰值低于静音门槛的分段已提前跳过，不会通过该步骤补救。

这是简单幅值放大，不是降噪、语音分离或回声消除。loopback 可能录入同一输出设备上的其他应用声音。避免同时播放无关音频；有重叠声音时不能承诺 ASR 会分辨直播和其他声源。

### 同时开多个任务出现音频混杂

API 允许创建多个任务，但当前没有单任务互斥或录音设备隔离。每个任务打开一个页面，并录制系统默认扬声器的混合输出；因此多个直播可能互相污染录音。为获得可解释的结果，一次只运行一个有声直播任务。并行请求能力不等于隔离的多路音频转写能力。

## ASR 后端与模型

### 实际没有使用预期的 FrameNotes / faster-whisper

后端选择不是请求参数，而是运行时条件：`REDBOOK_FRAMENOTES_ROOT` 指定目录下存在 `scripts/transcribe-audio.ps1`，并且 PATH 可以找到 `powershell`，才走 FrameNotes。默认 FrameNotes 路径为本项目根目录的同级 `FrameNotes`。

检查当前配置，不读取任何转写内容：

```powershell
Get-Command powershell -ErrorAction SilentlyContinue
$env:REDBOOK_FRAMENOTES_ROOT
python -c "from redbook_stream_notes.config import settings; print(settings.framenotes_transcribe_script); print(settings.framenotes_transcribe_script.exists())"
```

如果需要指定外部脚本所在仓库，在启动服务之前设置：

```powershell
$env:REDBOOK_FRAMENOTES_ROOT = 'C:\tools\FrameNotes'
```

环境变量需传给实际启动服务的进程；另一个终端中的设置不会改变已运行服务。模块导入时创建配置对象，修改变量后要重启服务。虽然依赖列表含 `python-dotenv`，当前没有调用其加载函数，因此 `.env` 文件不会自动生效。

只安装 `pwsh` 并不能满足代码对 `powershell` 的命令查找。若脚本或此命令不存在，服务选择 faster-whisper。当前没有显式的 `asr_backend` 请求字段。

### FrameNotes 脚本失败后任务直接 `failed`

这是当前行为：外部脚本返回非零退出码时，任务使用脚本的 stderr 作为异常消息，不会自动再尝试 faster-whisper。退出码为零后，服务仍要求音频同目录存在 `transcript.json`；缺失或格式错误也会失败。

FrameNotes 必须能接受音频路径位置参数，以及 `-Model`、`-Language`、`-Device` 参数。输出 `segments` 中每项至少应提供 `index`、`start`、`end`、`text`；`start/end` 应为该音频内的秒数。外部脚本兼容性不能仅凭文件存在判断。

先查看 `error`，再核对该具体段的 JSON 是否完整。当前调用捕获但丢弃脚本 stdout，因此服务快照不是完整的外部脚本调试日志。

### `auto` 没有使用 GPU，或显式 GPU 配置失败

faster-whisper 分支把 `asr_device: "auto"` 明确改为 `cpu`，并固定使用 `compute_type="int8"`。它没有自动探测并选择 GPU，也没有 CPU/GPU 失败重试。FrameNotes 分支的 `auto` 行为由外部脚本决定。

显式设备、模型与计算类型组合是否可用，取决于实际安装的后端和运行环境；仓库没有硬件依赖检测或可配置的 `compute_type` 字段。先用默认 CPU 配置确认整条链路可用，再处理具体硬件错误。不要在未验证的情况下声称已使用 GPU。

### 模型初始化慢、转写失败或没有识别到内容

fallback 模型在首次需要转写的非静音分段加载，每个任务独立保存模型实例。模型未缓存时可能需要准备模型文件；网络、磁盘、模型路径或资源不足的问题会在 ASR 阶段暴露。代码没有模型下载进度 API。

错误语言代码、不可用模型路径或设备配置也不会在 `POST /jobs` 时完成验证。保留具体 `error`，核对录音确为可辨识语音，再用已知可用配置重建新任务。当前没有修改现有任务参数或只重试某一失败分段的接口。

非静音不等于有人讲话。fallback 开启 VAD，音乐、噪声或很弱的语音可能产生空 `segments`；仍可能有 `transcript.json`，且 `chunks_completed` 会增加。

### `ZoneInfoNotFoundError` 或找不到 `Asia/Shanghai`

笔记生成使用标准库 `ZoneInfo("Asia/Shanghai")`。如果系统和当前 Python 环境没有可用时区数据，录音/转写之后的笔记构建也可能导致任务失败。按错误信息检查环境；可在当前 Python 环境安装时区数据：

```powershell
python -m pip install tzdata
```

重新验证时区是否可解析：

```powershell
python -c "from zoneinfo import ZoneInfo; print(ZoneInfo('Asia/Shanghai'))"
```

这是数据依赖问题，不应通过删除录音目录处理。

## 停止与直播结束判断

### 点了停止，页面还显示 `stopping`，浏览器尚未关闭

停止接口只设置停止事件，并最多等待 5 秒。当前完整录音分段和 ASR 不支持中途取消；需要等待正在进行的步骤结束。默认 60 秒录音加上 ASR 耗时，可能显著超过接口等待时间。

发出一次停止后轮询状态即可，不要通过重复停止加速。将来需要更短的响应时间时，可在创建新任务时降低 `chunk_seconds`，最低为 15 秒；现有任务没有动态改段长接口。

任务在最终关闭浏览器之前就会写入 `stopped`，因此终态快照出现与窗口消失之间也可能有短暂差距。强行关闭进程不能保证最后一段和精炼笔记完成。

### 已结束任务被再次停止后卡在 `stopping`

当前 `/stop` 不检查任务是否已经处于终态。它会将已经 `stopped` 或 `failed` 的任务也改为 `stopping`，而原后台任务已结束，不会再次修改状态。这是实现限制。

对任务先读取状态，只对活动任务调用停止，并且不要在 `stopping` 状态重发。如果已经触发此问题，依据停止前的终态、已有输出和进程日志判断实际完成情况；没有恢复该任务状态的公开接口，也不应把“再创建一个任务”描述为旧任务恢复。

### 直播还在播放，任务提前结束

查看 `ended_reason`。检测逻辑只检查页面正文前 5,000 字和全部 `video/audio` 元素的 `ended` 属性：正文出现 `直播已结束`、`直播结束`、`主播已离开`、`主播暂时离开`、`本场直播已结束`、`已下播` 或 `回放` 中任一词，就判定结束；任一媒体元素结束也会触发 `media-ended`。

这些词可能出现在与当前播放无关的文案里；“主播暂时离开”也可能只是短暂中断。当前没有主播放器识别、连续多次确认、结束词上下文判定或误判自动恢复。检查当前页面证据并向用户说明本次提前结束的原因；需要继续时创建新任务，其时间轴和目录从头开始。

### 主播下播了，任务仍在继续或一直录静音

结束检查只在每段录音前后执行，ASR 期间不会实时检查页面。如果网站不显示上述关键词，且媒体元素没有置为 `ended`，代码可能无法识别下播。返回值 `anyPlaying` 目前不参与停止决策，`paused` 和 `readyState` 也不会单独触发结束。

连续静音不是下播条件。可根据用户授权手动停止，或在建任务时设置 `max_chunks` 限制段数。不要承诺此实现一定自动识别所有下播页面。

## 笔记、输出与时间轴

### 找不到 `runtime/jobs` 或文件写到了别的目录

裸 Uvicorn 启动时，`runtime_dir` 默认是相对于服务进程工作目录的 `runtime/jobs`；CLI `scripts/redbook.py serve` 则固定为 skill 根目录下 `runtime/jobs`，或使用 `--runtime-dir` 指定的目录。先核对启动方式及 serve 打印的 Job files 路径。`REDBOOK_FRAMENOTES_ROOT` 只影响外部 ASR 脚本位置，不改变输出目录。

当前没有输出根目录 API 请求参数，`Settings` 也没有从环境变量读取 `runtime_dir`。只设置一个类似 `REDBOOK_RUNTIME_DIR` 的变量不会改变行为；使用 CLI 的 `serve --runtime-dir PATH`。

### 没有 `refined_note.md`，或它不是当前滚动笔记

精炼笔记只在正常结束收尾时、且存在至少一个转写片段时写入。任务仍在运行、全程无片段、或者因异常进入 `failed` 时，都不能保证有此文件。实时 API 的 `note` 返回滚动笔记，不是精炼文件。

`note.md` 也不是创建任务时立即存在；初始提示先保留在内存中。静音段会用静音提示覆盖此前 `note.md`，但不会清空任务内存的片段。之后成功转写或正常结束生成的精炼笔记仍可使用累计片段。

出现问题时保留当前任务的音频和原始转写用于核对。服务没有统一“导出所有转写”接口；可在进程仍运行时保存完整快照，或按后端时间约定读取具体分段 JSON。

### 文字时间码与真实直播时刻对不上，片段间丢话

这是当前架构的限制。录音、音量分析、ASR 和写笔记按顺序执行，没有持续录音线程与转写队列。转写上一段时发生的直播内容不会录到下一段。

时间码仍按“已经完成分段数 × 段长”推进，因此没有计入预检和 ASR 间隔，也不对应主播开播时间。静音正式段会占据时间轴。最后一条片段的结束时间只是累计片段时间坐标，不应描述为完整直播的时长或连续覆盖证明。

每段独立 ASR，也没有跨段重叠、句子接续或说话人分离。长句恰好跨段时可能被截断；换小段长会增加处理次数，也不能保证无间隙。

### 摘要内容不准确，清理后误改专有词

滚动摘要是高频词、句子截取和每 8 条片段的时间线组合。精炼笔记使用固定替换表、正则口头词清理和领域规则，没有额外调用大语言模型，也没有事实核查。

现有纠错和摘要规则明显偏向财经直播：部分输出是预写的板块、指数和资金流解释，由关键词共现触发。相关词同时出现不代表主播说过该完整结论；清理正则也可能误删正常语句中的字词。文件标题中的“精炼”不构成准确性保证。

向用户交付前用原始片段、时间位置和必要的音频核对关键数字、术语、因果关系及结论。不能把规则补出的内容当成逐字稿或把财经规则的表现推广到所有主题。需要调整领域时，应明确修改并验证 `notes.py` 的对应规则，而不是声称已有可配置的通用词典或主题插件接口。

### 页面只显示部分片段，SSE 长时间没有更新

内置页面仅渲染最后 250 条片段，`note.md` 的“原始转写”仅展示最后 80 条；API 快照的 `segments` 仍累计全部片段。精炼时间线最多 12 条，不能用于完整还原所有发言。

SSE 约每 2 秒检查一次快照签名，发生变化才发送，并不是每 2 秒必发心跳。长录音或长 ASR 期间没有新内容是可能的。先用普通 `GET /jobs/{job_id}` 区分“任务尚未更新”和“流式连接断开”。

客户端重连会收到当前完整快照，没有事件 ID 或历史增量重放。代理缓冲或断开时可先用本地直连排查；项目设置了禁止缓存/缓冲的 SSE 响应头，但没有实现完整的代理部署配置。

## 已有验证能说明什么

仓库测试覆盖健康接口、查看器 HTML 中的流式 UI、近期任务接口、未知任务事件流的 404，以及部分笔记生成和日期格式。它们不会实际登录小红书、播放直播、调用物理 loopback 设备、加载 ASR 模型或验证整场录制连续性。

通过单元测试只能证明对应代码路径的断言通过。准备交付真实监听结果时，应另外完成一段有实际可听语音的人工冒烟验证，检查其 WAV、转写片段、状态和输出文件；不要用测试通过替代此验证。
